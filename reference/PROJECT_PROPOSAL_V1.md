# 文欣安全通學 GO！3D 人本交通探究遊戲完整開發企劃
版本：V1.0／2026-11-01／狀態：待校方審閱與現地核定

## 一、計畫摘要
以桃園市龜山區文欣國民小學周邊真實環境為藍本，建置可在電腦、平板、手機瀏覽器操作的卡通 Low-poly 3D 通學遊戲。學生實際操控角色、等候交通工具、辨識路權、避開交通風險，並在「人本交通設計師」模式觀察環境、找出證據、拖曳設施、比較改善前後結果。遊戲是情境體驗與可觀察表現評量，不以持續文字輸入或選擇題為主。

核心使命：真實路網、卡通視覺、動手做中學、遊戲內評量、人本環境改善。
目標：國小一至六年級分級體驗；教師課堂投影與小組合作；評鑑展示；親子共同操作。

* 已確認：桃園機場捷運 A8 長庚醫院站官方位置為桃園市龜山區文化一路6號；出口1在文化一路與復興一路交叉口東南側；官方站頁提供轉乘公車資訊。來源：https://www.tymetro.com.tw/tymetro-new/tw/_pages/travel-guide/A8
* 待核實：校門入口座標、方向、道路單雙向、行穿線與號誌實際位置、校車停靠區、補習班接駁車動線、各路線學生實際搭乘方式、無障礙通道與交通尖峰觀察；不可自行推測或編造。
* 地圖來源規則：實測照片、校方提供的平面圖及政府開放圖資優先；如使用 OSM，遵守其授權與標示；不得直接抓取商業地圖圖磚重製未授權素材。公開遊戲不要繪製學生住址或個人常走路徑。

## 三、範圍與目標使用者
角色：低年級玩家（高指引模式）、中年級玩家（任務模式）、高年級玩家（觀察改善模式）、教師（展示/學習單/匯出）、管理者（未來版本）。
首版以可獨立運作的前端為準，不要求登入、不採集姓名、學號、GPS、影像或聲音；預設在本機儲存匿名遊戲進度。後續雲端統計須獲校方授權與資料保護設計。

## 四、遊戲場景分層（地理正確性約束）
L0：學校平面地圖校核。L1：真實地標、道路網、行穿線、號誌、車站出入口與候車點；L2：按比例簡化距離及建築量體；L3：卡通美術、樹木與裝飾。L1 嚴禁用美術需求擅自變更。未確定點位顯示「示意／待現地核實」。
場景 A 學校門口（人車分流）、B 周邊路口（轉彎車與視線遮蔽）、C A8 站外與站內（月台/門扇/電扶梯/無障礙電梯）、D 公車候車點與車廂、E 校車停靠與車廂、F 補習班接駁區、G 多模式轉乘節點、H 人本交通改善沙盒。

## 五、八組核心可操作小遊戲（不以純答題取代互動）
| 小遊戲 | 玩家實際操作 | 概念與觸發回饋 | 遊戲化評量證據 |
|---|---|---|---|
| 1 安全路口探險 | WASD/虛擬搖桿步行、停止、左右轉視角、等待號誌與觀察轉彎車 | 安全路徑、行人優先與駕駛停讓責任；碰撞前採安全暫停而非事故動畫 | 停看觀察行為、是否選擇合法穿越處、重新修正次數 |
| 2 A8 捷運任務 | 移動至正確出口、扶梯站穩、月台站在線後、等人下車再進車廂 | 站內禮儀與車門安全；視覺高亮、短語音與重演 | 候車位置、搶門次數、上下車順序 |
| 3 公車站守護者 | 找候車安全區、排隊、等停妥上車、扶握、按鈴、下車後等待視線清楚再過街 | 不追車、不從大型車前後貿然穿越 | 動作時機、安全距離、完成率 |
| 4 校車安全隊長 | 依序候車、選座、扣好安全帶（依實車配置）、下車後安全行走、模擬清車點名 | 乘車秩序、車內安全、下車避免死角；不得把清車安全責任歸給兒童 | 上車序、繫帶/坐定、離車安全 |
| 5 補習班接駁任務 | 比對約定接送標誌、跟隨指定路線到接送區、車停妥再上車、錯車選擇求助 | 核對車輛與負責成人、不任意跟陌生人走 | 核對步驟、是否向師長求助 |
| 6 家長接送任務 | 下車前選擇安全側、下車後遵循人車分流步行 | 區分安全上下車地點、車門風險 | 選擇安全開門方向與路線 |
| 7 多模式轉乘拼圖 | 將步行、捷運、公車、校車、接駁按任務串接，操作安全轉換點 | 轉乘是風險最高的節點之一；體驗因路線不同而變 | 路徑安全度、轉乘風險辨識 |
| 8 人本交通設計師 | 360 度觀察、點選風險熱點、拖曳人行道/護欄/庇護島/無障礙坡道/接送站區，按「模擬」查看行人與車流 | 兼顧兒童、行動不便者、長者、駕駛與公共運輸，避免僅要求兒童自行閃避車輛 | 發現風險種類、提出措施適配性、理由圖卡與改善前後比較 |

每關由四段組成：5–15 秒情境動畫 → 1–3 分鐘真實操作 → 錯誤時即時圖示／語音概念解說 → 重新嘗試與一張「安全觀念卡」。不以失誤扣血、羞辱或恐嚇兒童；可以無限重試。教學結論與號誌以官方規範校核。

## 六、無長篇輸入的評量機制
以遊戲事件記錄證據：停下、轉頭看、等待、正確區域、扶握、讓行、核對接駁、完成安全轉乘、改善設施配置。以四層級評量：初探（需提示）、進步（提示後正確）、熟練（能獨立完成）、設計者（能舉證改善）。不用競速排名作為主要安全指標；分數包含安全決策 40%、風險觀察 25%、實際操作 20%、反思改善 15%，權重為建議值可調整。
回饋形式：短動畫、角色旁白、單句字幕（國字與注音可切）、顏色形狀提示、示範重播；可關閉音效、調低動態效果，提供純點選模式和鍵盤可及替代。
評量小遊戲例：拖曳「讓行空間」而不是填空；點選危險點而不是寫段落；觀察倒數時序而不是答題；組合「問題→改善→受益對象」圖卡而不是輸入作文。
學生高年級自訂意見為可選，教師可以手動匯出匿名成果。

## 七、跨年級課程整合
低年級：生活／健體；辨識、模擬、跟隨安全路線。中年級：綜合／社會／數學；比較轉乘、統計危險點、繪製安全圖。高年級：科技／藝術／社會與綜合；使用實景證據進行人本設計，展示改造前後與多方權益。
學習目標：安全辨識、情境判斷、應用與遷移、證據導向改善；正式教案的核心素養/領綱代碼需查證官方版本後編列，不捏造編碼。
SEL 適切融入：社會覺察（體會輪椅使用者、幼童與長者）、負責任的決定（衡量改善措施對不同用路人的影響）、人際關係技巧（團隊討論）。不評分情緒或人格。

## 八、技術架構（Codex 可直接實作）
* Node.js LTS、TypeScript、Vite、Three.js（真 3D WebGL，不用 CSS 假 3D）、原生 HTML/CSS UI；初版不使用後端及付費 API。
* 3D：GLTF 場景和簡化低多邊形模型；使用幾何體建立首版站牌、車輛、人行道、紅綠燈及校門；後續替換成有授權的模型。
* 狀態：單向有限狀態機 scene -> objective -> perform -> feedback -> finish；scenario 與 rubric 用 JSON 資料驅動，不把文字寫死在引擎。
* 操作：桌機 WASD/方向鍵/滑鼠、平板與手機左手虛擬搖桿+右手點選、單手點選導航模式，暫停、自動提示、易讀圖卡；基於 Pointer Events 防止雙擊與拖曳觸摸衝突。
* 縮放：3D 相機跟隨與限制旋轉，避免暈眩；低階裝置降低陰影與解析度。
* 存取：匿名 localStorage 進度、JSON 匯出，可清除資料；不使用任何學生識別資訊。
* 部署：Vite dist 靜態檔部署 GitHub Pages；設定正確 base 路徑；以 HTTPS iframe 或連結整合 Google Sites，視 Google Sites 嵌入政策測試。
* 測試：Vitest 單元測試（規則、狀態、計分）；Playwright E2E（滑鼠/鍵盤與行動裝置模擬），實機 Safari/iOS 與 Android 再人工測試。

## 九、模組與資料定義
`Scenario`: id, category, mapZone, gradeBand, learningObjectives[], interactions[], hazardIds[], cues[], failureFeedback[], successFeedback[], eventRules[], rubric.
`MapFeature`: id, type, position[x,y,z], orientation, isVerified, source, observedAt, safetyRuleIds[].
`HazardObservation`: hazardId, sceneId, kind, evidenceChoice, impactedGroups[], confidence, noStudentPII.
`Improvement`: optionId, hazardIds[], affectedGroups[], costTier, expectedEffect, tradeoffs[], requiresRealWorldExpertReview.
`PlayEvent`: timestampRelative, scenarioId, eventType, promptUsed, corrected, outcome; never store precise geolocation or student names.

## 十、分階段開發與驗收
P0：環境與場景資料核實（校圖、官方捷運資訊、校門/站牌/接送點實測）→ 校方核定的場景基線，禁止臆測。
P1：MVP 3D 場景與角色（校門、路口、A8 示意、鍵盤／觸控移動）→ 可在電腦和手機進入 3D 世界並移動。
P2：6+2 個實操小遊戲（非純選擇題）→ 每種交通模式至少一關，具有錯誤提示與重試；至少一個真正環境改善關卡。
P3：教師頁與匿名成效報告→ 學習事件可核查、任務完成可匯出匿名記錄，無個資。
P4：場景現地比對、美術與可及性、效能驗收→ 逐項核對路口、標誌、校門、停靠位置，並完成手機、平板、桌機實測。

MVP 驗收：① npm install/npm run dev/build/test 成功；② WebGL 可見真實 3D 模型與角色；③ 觸控與鍵盤可操作；④ 最少六類通勤方式都可完成一個實際操作任務；⑤ 錯誤有短動畫/圖卡解釋且可重試；⑥ 人本設施可拖放並模擬前後比較；⑦ 清楚標示未核地點；⑧ 預設零個資；⑨ 不把出錯歸咎於行人而忽視駕駛義務。

## 十一、治理與風險
安全：遊戲不能取代現場教師及導護指示；避免教學生穿越真實車流採樣。圖資：未核定場景加警示標籤。法規：站內規則與交通法規需由官方最新資料及校方審查。隱私：不用學生姓名學號、GPS、照片與自動追蹤。性能：低階設備可降畫質和動態效果。無障礙：提供字幕、非聲音線索、色盲可辨標示、非精準拖曳替代控制。

## 十二、預估工期與資源（規劃參考，非承諾）
