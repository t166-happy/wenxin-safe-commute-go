# 文欣安全通學 GO! - Codex 情境更新規格 v1.1

日期：2026-11-01
定位：供既有 Codex 專案合併的增量規格，不取代主企劃。

## 核心約束
- 真實世界基準：文欣國小（桃園市龜山區文昌五街95號）；周邊文昌五街、文化一路、復興北路；機場捷運 A8 長庚醫院站。捷運 A7 體育大學與 A9 林口分別位於 A8 兩側，站序須依官方路網。
- 僅使用已核對的站點、道路或經校方確認的校車及補習班接駁點。其他點位以「示意候車點」標識，不得聲稱是實際路線。
- 低多邊形卡通 3D 可調整比例、細節，但不可虛構道路通行方向、號誌、站位、行人動線與列車停靠模式。
- 無需學生輸入長篇文字；操作、拖放、排序、圖卡、動畫、音效回饋為主。錯誤時停止危險動畫、顯示原因與正確做法並允許重試。
- 教育上不得把駕駛禮讓行人等法定責任完全轉嫁給學童。

## 場景 1：步行通學
起點：經驗證的周邊街道位置（預設示意文昌五街社區口）；終點：經校方核對的校門入口。
流程：自由行走 -> 人行通道 -> 路口停候 -> 觀察號誌和轉彎車 -> 走行穿線 -> 校門人車分流 -> 完成。
操作：WASD/方向鍵/觸控搖桿移動；鏡頭拖曳轉向；眼睛圖示檢視遮蔽角；紅綠燈與來車反應；走對路線。
評量：是否路口停候、觀察視角、選對穿越處、確認車輛停讓、無逆向亂穿；不要單靠速度。

## 場景 2：機捷 A7/A9 至 A8
提供 A7 -> A8 與 A9 -> A8 兩條路徑，均需依正確路線及普通車停靠資訊配置。不能誤教直達車每站停。
流程：站外辨識入口 -> 進站閘門 -> 檢視方向指示 -> 進入正確月台 -> 安全線內候車 -> 車停妥開門 -> 先下後上 -> 站穩或就座 -> A8 下車 -> 出站 -> 步行校園（實際動線待驗證）。
操作：角色走動、點選閘門、識別方向牌、在候車區站位、使用扶手互動、下車時機判斷。
評量：搭對方向、月台安全、上下車秩序、車門警示、搭車姿態、出站接續安全。

## 場景 3：公車站至學校
起迄公車站、路線編號由運輸主管機關站牌清單與實地調查核定後填入；開發時以標示清楚的「示意站點 A / B」建立可替換場景。
流程：步行到站 -> 查站牌方向 -> 安全等車 -> 車停穩上車 -> 刷卡或依實際規則搭乘 -> 入座或扶穩 -> 下車前按鈴 -> 下車停留安全處 -> 不從車前後突然穿越 -> 步行到校。
操作：方向選擇、路線牌比對、扶手點擊、按鈴時機、視線死角掃描。
評量：候車位置、選車、車內安全、下車及安全轉步行。

## 場景 4：校車上下學
起迄站由學校核實，暫以「示意社區候車點」。設計上學及放學雙向模式。
流程：候車點 -> 與車輛保持安全距離 -> 停穩後上車 -> 依序就座/依實際車種繫安全帶 -> 途中保持安全 -> 下車前整理 -> 車停妥及獲指示後下車 -> 遠離車輛視線死角 -> 依指定校門動線通行。
操作：排隊位置、上車時機、座位與安全帶互動、下車等待、離車動線。
評量：是否忽略車門、是否穿越車頭、是否遵守乘車安全及隨車人員指引。

## 場景 5：補習班接駁
從校方確認的放學集合區開始；避免公開具識別性的學生名冊和私人車號。
流程：集合 -> 比對經授權確認的接送標誌/人員 -> 車停穩 -> 排隊上下車 -> 車內安全 -> 到站下車 -> 確認周遭車流。
操作：辨識被授權車輛、選候車位置、上下車時機、車門安全區。
評量：確認接送對象、動線、乘車安全。

## 場景 6：人本交通設計師
從遊戲各場景收集證據（照片式截圖/風險標記）：無連續人行道、視線遮蔽、接送動線重疊、候車空間狹窄、無障礙阻礙等。
以拖放形式安置：行人通行空間、路口視距改善、照明、無障礙坡道與導盲動線、接送分流、減速設施。改善方案需依主管機關規範作為討論模型，不代表可任意施作。
顯示改善前後的模擬視線、衝突點與無障礙可達性；學生以「問題位置 + 風險種類 + 改善設施 + 受益者」四張圖卡提出改善建議，文字補充為選填。
評量基準：有證據、符合安全原理、照顧不同用路人、能說明取捨；避免只用點數獎勵單一標準答案。
SEL：社會覺察、負責任的決定、人際關係技巧；以協商、證據和設計理由作觀察評量，不評斷人格或情緒。

## 通用 UI / 評量
- 3D 操作：桌機鍵鼠、平板與手機虛擬搖桿、相機視角旋轉；提供低效能模式與替代點擊操作。
- 避免大量文字：語音可關閉、字幕可開啟；短解說卡、可回放示範動畫、圖像化提示。
- 一關 3~6 分鐘，含觀察、操作、反思，允許重試、跳過眩暈動畫及調整字體。
- 事件記錄：mission_id、scene_version、action、outcome、hint_used、retry_count、anonymized_session；不得收集姓名或精確居住地；預設本機儲存，匯出需明確操作。
- 評量：危險辨識、安全操作、判斷理由、改善建議四面向；重視學習進步與重試，不公布學生排名。

## Codex 實作順序
1. 將場景資料抽離為 JSON/TS 結構（locations、routes、stops、risks、learning_goals、verified_status、source_url）。
2. 先完成可操作步行 3D 關卡及可移動交通車輛、號誌、觸控控制、事件評量。
3. 完成 A7/A9 -> A8 捷運月台與乘車狀態機，確保方向/停靠站正確。
4. 完成公車與校車完整上下車流程，再擴充補習班接駁。
5. 完成人本交通圖卡拖放、改善前後視覺比較、匿名成果匯出。
6. 自動化測試主要任務狀態轉移與錯誤回饋；實機測 Chrome/Edge/Safari、桌機/平板/手機。

## MVP 驗收條件
- 角色在 3D 場景中能自由移動並與交通設施互動，不是僅靠選擇題過關。
- 捷運 A7/A9 分別能正確搭至 A8；錯誤月台或列車必須觸發可理解的矯正回饋。
- 步行、校車、公車每條路線含至少 4 個實際操作事件，且雙向通學可用。
- 各關按行為紀錄評量；危險操作不作為可重演的刺激懲罰動畫。
- 改善任務可保存由圖卡組成的建議及匿名匯出。
- 遊戲具備基本鍵盤與觸控功能；無網路下核心素材可運行（若部署策略支援快取）。
