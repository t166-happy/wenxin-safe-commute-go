# 文欣安全通學 GO！ V1.4 全通勤實作遊戲規格

## 0. 專案定位
本文件為既有 V1.0-V1.3 Codex 專案的增量開發規格；保留校車/補習班接駁、導護站與人本交通設計。**禁止**將遊戲退化為單純選擇題，禁止把未經核實的站牌、路線、接送點標記為真實。真實街廓可卡通化簡化，惟車行方向、穿越位置、月台/候車動線、安全措施須按查證與現勘資料。搭車班次與公車路線為資料驅動、可更新。

## 1. 共通遊戲回合
從出發點選擇→角色控制前往目的地→觀察風險→按照時序操作→禮貌互動→抵達與安全確認→以短動畫/圖示/口語解說→再試一次→取得分項徽章→可選的人本交通改善任務。

### 必須使用的互動原語
MOVE（搖桿/鍵盤行走）、LOOK（轉動視角）、WAIT（停等）、NOTICE（點選風險）、INTERACT（感應/刷卡/按鈴/抓扶手/安全帶）、QUEUE（移動至隊列定位點）、BOARD/ALIGHT（上下車動畫）、SEAT（定位座位）、GREET（選圖像或動畫表達尊重）、HELP（向適當人員求助）、IMPROVE（拖放環境改善物件）。不以文字輸入作為必要通關條件。

### 評量規則
安全是必要門檻，不與禮貌分數互相抵換。依事件紀錄達成/未達成/已重試，計算五種能力：危險覺察、安全決策、順序操作、社會互動、人本改善。個別失誤給予示範與重試，不呈現碰撞傷害畫面、不鼓勵冒險搶時間。禮貌不強迫言語或視線接觸，點頭/揮手/文字圖示均為等價表達。

## 2. 步行完整連續關卡
**地理**：從文昌五街等經查證之鄰近街道示意起點至校門，附選擇性文化一路/復興北路周邊路口子場景；先以待驗證節點構成路網，不自稱實際行穿線位置。
**序列**：起點整裝→沿安全路徑行走→遇停放汽機車視線遮蔽時退至可見位置→到巷口減速停看→辨識行人號誌及轉彎車→確認駕駛停讓後使用行穿線→遇導護站依合理指引等候→行人安全通行→進校向導護人員表達感謝。
**操作小遊戲**：A 路線追蹤（玩家走而非自動畫線）；B 轉鏡頭尋找被車遮蔽風險；C 動態號誌與轉彎車判斷（時間非得分要素）；D 導護 STOP/GO 多訊號判斷；E 禮讓輪椅與幼童、維持動線。失敗演示「停下與重新觀察」，不以碰撞方式懲罰。
**安全規則**：有綠燈仍需留意車輛；導護指示不能凌駕法令及號誌；遇到違法/不安全駕駛，學生應在安全處等待，勿自行攔車。

## 3. 機場捷運完整連續關卡
**地理**：從真實可驗證之 A7 體育大學站或 A9 林口站出發，搭往 A8 長庚醫院站；路線方向與列車停靠種類以官方站序與營運資訊資料決定；避免假設所有車種都會停靠每站。A8 出站後步行至校園，出口與街道先待校核。
**序列**：從站外步行→找入口/無障礙動線→通過閘門→識別方向與停靠資訊→搭電梯或依安全規定使用手扶梯→在候車線後等候→先下後上→進車廂站穩扶好/入座→觀察報站→A8 下車→出閘→走安全路線至學校。
**小遊戲**：A 圖示找正確方向/適合車種；B 月台排隊定位與車門安全；C 車門警示時止步；D 車廂扶手操作及禮讓；E 出站與行人通學挑戰。
**禮儀**：不推擠、不阻擋車門、禮讓有需求乘客、合理音量；需要協助時向站務人員求助。不要求學生在任何情況下與陌生人接觸。

## 4. 公車完整連續關卡
**地理**：站牌與路線採 config 可編輯；只顯示經查證的實際站名與路線，資料缺漏時採「示意站 A」和「示意站 B」。不得擅自指定會停靠校園的線路。
**序列**：沿人行動線走到候車點→站牌安全區候車→識別方向及車號→車完全停穩才靠近→依序上車、感應票卡→確認座位/握緊扶手→避免干擾司機→接近目的站按下車鈴→停穩依序下車→不從公車前後緊貼穿越→找合規行穿線步行到校。
**小遊戲**：A 站牌辨識；B 站位和排隊；C 上車感應；D 煞車情境握扶手；E 按鈴時機；F 車外視線遮擋與安全繞行。
**禮儀**：問候、禮讓、保持車內安靜、愛護設施及向司機適時致謝；如需協助，在車停穩或安全時機提出。

## 5. 校車與補習班接駁整合（繼承 V1.3）
候車定位→依序排隊→車停穩→隨車人員引導上車→識別虛擬座位編號→座位安全帶→車內安全/求助/良好互動→停穩後依指引下車→確認同行名冊/接送交接（僅模擬 ID）→安全離開。補習班接駁加「核對車輛與經授權接送者」流程；絕不在公開網站展示真實學生名冊、車牌與班級資訊。

## 6. 轉乘與整合
捷運+步行、公車+步行、校車+步行、補習班車+步行：沿用各模組事件，最終進校導護站流程。不同交通工具切換不可跳過下車安全。

## 7. 人本交通改善模式（所有關卡都可觸發）
**觀察**：玩家用相機角度查看遮蔽、狹窄步道、違停、候車區不足、車輛衝突點、坡道/導盲設施；選擇至少兩個證據點截圖。
**提出方案**：拖放候車排隊線、行人空間、無障礙坡道、庇護設施、減速設施及人車分流設計（不保證現地都可直接施作）。
**看影響**：以可解釋的簡化模擬比較改善前後行人衝突點、無障礙可達性和候車秩序。呈現『建議供權責機關評估』而非真實工程可行性認定。
**反思**：三張圖卡選擇「我發現什麼、對誰有幫助、還須確認什麼」；高年級可選填文字/語音，不強制。

## 8. SEL 融入與可觀察證據
自我管理：面對催促仍選擇安全停等；社會覺察：辨識幼童、長者、輪椅等不同需求；人際關係技巧：排隊、與司機/隨車人員/導護老師適切互動；負責任的決定：選擇符合法規且能兼顧他人的路線或設施。僅評估行為，不標籤個人情緒或人格。

## 9. 跨裝置與無障礙
電腦 WASD/方向鍵、滑鼠鏡頭；手機/平板螢幕左側虛擬搖桿、右側鏡頭與大尺寸互動鍵；可暫停，可減少動態、可切換固定鏡頭、字幕/圖卡取代語音、色盲友善號誌識別、操作時間可延長。建議 30fps 最低可用、目標 60fps，實機測試決定。適配直橫螢幕；不依賴 hover。

## 10. 程式架構（Codex）
- Vite + TypeScript + Three.js；場景 config 與行為 FSM 分離。
- `src/scenes/{walk,mrt,bus,shuttle,transfer}/`、`src/gameplay/{fsm,interaction,assessment,feedback}/`、`src/data/{map,stations,stops,scenarios}/`、`src/ui/{controls,accessibility,results}/`。
- JSON schema：`scenarioId`, `verifiedGeography`, `nodes`, `vehicles`, `phases`, `objectives`, `safeActions`, `unsafeActions`, `feedback`, `selTags`, `evidence`; `verifiedGeography` 初始 false 直到校核。
- 全部事件本機匿名儲存，公開測試禁個資、無第三方學生追蹤；正式記錄需校內核准。

## 11. Codex 開發順序與驗收條件
P0：建立四類 FSM、匿名事件紀錄、跨裝置控制、3D 示意路網，啟動 `npm run dev`。
P1：步行完整路口與導護站關卡；使用者能自行移動、停看、觀察車輛、通過而非點下一題。
P2：捷運上下車與方向辨識；可從起站走到 A8 出站，保證路線、停靠與上下車邏輯正確。
P3：公車候車、上下車、車內安全、按鈴、下車後行穿線。
P4：整合校車/接駁 V1.3 編號入座、交通禮儀與緊急求助。
P5：人本改善拖放方案 + 教師匿名儀表板 + 可匯出教學證據。
每個 P 必含單元測試（FSM/安全判斷）、端對端操作測試、手機/平板/桌機的操作測試記錄。含照片/圖資引用時須記錄來源、授權與查證日期。

## 12. 立即交給 Codex 的任務
請閱讀本檔、原 PROJECT_PROPOSAL.md、AGENTS.md、V1.1/1.2/1.3 更新。以增量方式實作 V1.4；第一步先檢查現有 repo、列出已實作與缺漏、提交 P0/P1 的可執行程式與測試，之後依 P2-P5 擴充。不可只生成敘述/假畫面；每一個小遊戲都有可操作角色與可判定的狀態轉移。無法取得真實站牌資訊先用標示為示意的資料，不能猜測。完成後報告本地啟動命令、測試結果與尚未通過項目，不得宣稱已公開部署除非實測成功。
