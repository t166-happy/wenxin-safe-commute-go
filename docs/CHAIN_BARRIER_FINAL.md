# 校門前廣場固定設計規範：交通錐＋連續鏈條人車分道（定案）

## 唯一正式情境
依校方提供兩張照片作為位置、透視與配置參考，遊戲僅呈現改善後的「交通錐＋連續實體鏈條」分道。不得提供「只有交通錐」模式、任意跨越演示、從錐間鑽入車道之可操作動作。照片中可辨識：左側樹木綠地旁學生步行帶、中央導流交通錐、右側安親班接駁車停靠帶、前端人員引導。新設鏈條為遊戲目標配置，照片不是鏈條已設置的佐證。

## 場景與碰撞
1. 以左側為人行區、中央錐鏈分隔、右側車輛停靠區的相對關係建模，細節比例與停車方向需現場核對，不能臆測照片以外的交通規則。
2. 各交通錐之間以可見鏈條連接，鏈條沿人車分界連續，僅在「受控登車通道」形成真正受管理的缺口。避免低垂鏈條造成絆倒疑慮；真實施作高度、張力、無障礙與逃生要求需交校方專業評估。不得將遊戲配置視為現場工程施工圖。
3. 在整條人車邊界設定連續、不可穿越的物理碰撞體（collider），不能只在交通錐上設定碰撞。學生角色不可穿鏈、鑽洞、跳越、繞過端點、利用碰撞漏洞移動到車道。加入端點封堵及邊界測試。
4. 受控登車口預設關閉，必須先有車輛已停妥、車道停止移動、指派車輛辨識正確、導護／隨車人員確認、登車順序輪到玩家，才可開啟。任何條件失效立刻關閉，不能讓車輛與學生同時使用交會區。
5. 車輛按指定順序低速進場、停放、熄火／安全停車後進入上車程序，依校方既有 SOP 調整；兒童只走安全步行帶到集合點，不能追車。
6. 學生找到車輛編號後排隊、接受核對、於受控登車口通行、上車依虛擬座號入座、繫妥安全帶、禮貌向司機及隨車人員致意。不採用真實學生名單或車牌。

## 教育與互動
- 教導學生「有鏈條的地方不穿越；從指定登車口在成人確認後依序前進」，勿設計故意穿越錯誤通道來得分。
- 誤碰鏈條時角色停下，圖示＋語音：「這裡是人車分隔區，請沿安全步道前往指定登車口。」不扣羞辱性分數。
- 人本交通改善提案改為『已設鏈條情境下』觀察視線遮蔽、臨停秩序、接送動線、無障礙需求及緊急疏散；不提供拆除鏈條的選項。

## 狀態機與通關
`ARRIVE_FOOTPATH -> WAIT_AT_ASSEMBLY -> IDENTIFY_SHUTTLE -> QUEUE -> PARKED_AND_STAFF_CLEARED -> CONTROLLED_GATE_OPEN -> BOARD -> FIND_SEAT -> BUCKLE -> READY`。
`CONTROLLED_GATE_OPEN` 必須以邏輯 AND 驗證 vehicleStopped, vehicleCorrect, adultCleared, studentTurn, crossingConflictFree；不可僅以固定時間自動開放。

## 強制驗收
- 碰撞：從每兩只交通錐間嘗試穿越均失敗；跑步、斜切、角落、端點、手機觸控位移均無法越界。
- 入口：車輛移動時入口維持關閉；未確認身分與順序不開啟；車輛停妥不等於自動可登車。
- 遊戲：不需要大量輸入文字，使用角色移動、點選號碼、排隊及安全帶操作完成。
- 反饋：操作失誤提示正確方法並允許重試，不演示危險動作動畫作為通關捷徑。
- 校核：實際設施位置、鏈條高度與進出口依學校及安全人員核准資料修訂。

## 影像與隱私
提供照片僅作內部視覺參考；涉及未成年人的實拍人臉、身形細節及車牌不得直接公開為素材。正式遊戲使用重新建模的卡通人物與虛構車牌。

## Codex 指令
請將本文列為優先於任何 V2.0/V2.1 舊設定的強制規格，落實可見的連續鏈條與不可穿越的碰撞邊界，僅允許成人安全確認後通過指定登車口，新增自動化越界及交會安全測試。不得實作交通錐單獨分隔之可操作場景。
