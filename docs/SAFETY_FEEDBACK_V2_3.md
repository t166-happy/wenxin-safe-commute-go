# V2.3 全關卡交通安全正確性與即時矯正規格（強制）

## 0. 適用範圍與優先順序
適用步行、導護站、機場捷運、公車、校車、補習班接駁車、家長接送、轉乘與人本交通改善全部場景。此文件對「教學正確性、錯誤處理與安全性」具有最高優先序；校門廣場的實體鏈條、人車分道及受控登車口以 `CHAIN_BARRIER_FINAL.md` 為不可降低的底線。如有不一致，應同時滿足較安全、經驗證的條件並在 `docs/PROGRESS.md` 記錄待決事項。

## 1. 遊戲教學不可妥協的原則
1. 遊戲唯一示範的可通關流程須遵守當地有效交通安全規則、適齡教育原則與校方核准的導護/接送動線；不可用闖紅燈、穿越鏈條、搶車門、跳車、車行中離座等方式完成關卡或換取獎勵。
2. 對危險操作立即、平和且清楚地回饋：暫停玩家該動作／在危險界線阻擋角色（可停止遊戲內模擬場景），顯示危險位置、原因、正確操作的圖示/短動畫/字幕，可選擇重播；回到安全檢查點練習。不要以意外碰撞、受傷畫面或羞辱作為懲罰。
3. 錯誤是學習機會；記錄「首次判斷、是否接受提示、重試後是否正確」，並將初次表現與練習後掌握情形分開。不能用重試洗掉前測，但不限制練習次數。
4. 操作即評量：走、停、轉頭觀察、按車門/扶手互動、排隊、刷卡、對號入座、繫安全帶、選擇安全通道、拖放人本交通改善設施；不以打字或限時反應作為必要條件。
5. 以可理解的中文繁體短句、圖形/簡易動畫、可開關音訊解說提供回饋；圖示不可僅靠顏色辨識；觸控、鍵盤、輔助操作等效。
6. 交通法規、行車站序、現場設備與車輛特性需標示來源及查核日期。未查證的實際路線與停靠位置只可標示「教學示意」；不得把角色安全責任完全轉嫁給兒童，駕駛者禮讓/停車責任也須呈現。
7. 禮貌是正向加值，不可取代安全。口語表達以點頭、揮手、圖示或字幕替代；避免鼓勵兒童在道路危險位置停留致謝。

## 2. 通用回饋狀態機
`READY -> PLAYING -> SAFETY_CHECK -> (SAFE_CONTINUE | BLOCKED_FEEDBACK) -> RETRY_CHECKPOINT -> PLAYING -> COMPLETED`
- 每一個關鍵操作先由 `SafetyRuleEvaluator` 驗證角色位置、道路號誌、車輛移動狀態、工作人員放行權限、車門/安全帶/座號、障礙物碰撞等前置條件。
- 當 `blocked` 時：立即禁止該次互動；鏡頭指向危險源（無閃爍刺激）；提供「為什麼危險？」及「應怎麼做？」最多兩句短文；可點擊「看示範」「再試一次」。
- 允許不需危險碰撞也可觸發教育回饋（例如角色尚未確認左右來車就準備通行）。
- 錯誤提示必須指定 `ruleId`、`hazardId`、`severity`、`explanationId`、`correctiveActionId`、`checkpointId`；禁止通用「答錯了」取代觀念解說。
- 若關鍵資料缺漏或情境狀態不明，採安全失敗封閉（fail closed），不放行並標示「請依現場老師及交通設施指示」。

## 3. 每一關必備的錯誤事件與正確回饋
| 關卡 | 錯誤操作 | 立即矯正與重試 |
|---|---|---|
| 步行路口 | 未確認號誌/轉彎車就跨入車道、從停車車輛前後衝出 | 阻止進入車道，示範在安全位置停等、觀察號誌與車況、選擇合法行穿線，重試 |
| 導護站 | 未遵守現場合理導護引導，搶先通過 | 停在安全區，觀察導護人員和號誌；提醒以當地法規與實際路況為準；等安全放行後通過 |
| 機場捷運 | 跑進關閉中的車門、越過月台安全界線、逆向選錯月台 | 阻擋危險動作，以圖示示範排隊、先下後上、等下一班車與辨認正確方向 |
| 公車 | 站進車道候車、追車、從公車車頭前方突然穿越道路、車內不扶穩 | 阻止該行為，標示安全候車區、候車/下車後的視線遮蔽，示範按鈴、抓扶手/入座及合法穿越位置 |
| 校車 | 車未停穩就上/下、插隊、找錯座位、未繫安全帶、車行時起身 | 阻擋登車或發車、提示車輛停穩依序上下、依指定編號入座與繫帶，重試 |
| 補習班接駁車 | 穿越錐鏈、進入車道、選錯接駁車、車輛移動時登車 | 碰撞阻擋與受控登車口封閉，導引至行人區/集合點，待車停妥及人員放行再上車 |
| 家長接送 | 從車道側下車、未觀察後方來車就開門、穿越接送車流 | 阻止下車事件，示範車輛合法停妥、確認安全後從安全側上下車，依指定動線步行 |
| 轉乘 | 為趕轉車奔跑穿越道路、走錯出口/臨時改線 | 顯示不趕車的重要性、依安全路線/標誌轉乘，必要時尋求站務或老師協助 |
| 人本改造 | 封住無障礙通道、阻擋救援動線、設置造成視線死角的設施 | 拒絕不安全配置，說明對輪椅使用者、孩童或救護車的影響，改選可行方案 |

## 4. 實景校門廣場定案
照片僅用來校對空間相對關係：左側學生步道、中央錐鏈隔離、右側停放接駁車、前端導護引導；不得從照片推定實際尺寸、車道權利或人員身分。遊戲唯一正式場景為**每個三角錐以連續鏈條連接**，且鏈條是實體碰撞障礙，角色不能跨越或穿透。沿學生安全步道到集合點；車輛進場/移動時受控登車口鎖住；車輛停妥、無交錯車流、老師/隨車人員確認，才開放指定登車口依序上車。可留必要緊急/無障礙通道，但不得當作學生捷徑；須經現場安全審核。

## 5. 錯誤回饋介面設計
- 畫面立即浮現 `⚠ 請先停下`，柔和標示安全等待點，旁邊展示簡短兩步示範。例如：`車門正在關閉，不能衝上車。請退到候車區，等下一班。`
- 可點選 `看示範`、`再試一次`、`我需要提示`；無需文字輸入。
- 教學完成後繼續同一任務，不扣除安全生命值、不顯示血腥事故動畫、不鼓勵冒險行為。
- 需支援無音訊模式、字幕、適合色弱的圖示、較低動態效果。

## 6. 學習評量資料模型（匿名）
```ts
interface SafetyEvaluationEvent {
  sessionId: string; // 隨機匿名，無姓名學號
  sceneId: string; ruleId: string; hazardId?: string;
  eventType: 'safe_action'|'unsafe_attempt'|'hint_viewed'|'retry_success';
  feedbackShown: boolean;
  timestampMs: number;
}
interface RuleDefinition {
  ruleId: string; sceneIds: string[]; ruleText: string;
  sourceUrl?: string; sourceCheckedAt?: string;
  predicates: string[]; explanationId: string; correctiveActionId: string;
  isCritical: boolean;
}
```
展示學生首次操作風險辨識率、提示使用率、重試改善率、各概念掌握度；不得公開個別學生資料，不以失誤數進行學生標籤化。

## 7. 自動化與人工驗收門檻
1. 每關至少 3 個安全正確操作測試、3 個錯誤情境測試及 1 個無障礙/低動態操作測試；所有關鍵危險嘗試均必須被阻止並有可讀回饋。
2. 確認不能穿越鏈條、交通車未停穩不能上車、行車未繫帶不能發車、號誌不合法時不能過馬路、未經人員放行不能從廣場登車口通過。
3. 回饋不超過合理閱讀負擔、無需鍵盤輸入、重試可返回檢查點且不遺失學習歷程。
4. 任何交通安全內容在發布前必須由校內交通安全承辦/導護負責人核對實地現況，並保留法規/營運單位官方來源與審核紀錄；未審核不得標註正式完成。
5. 使用 Playwright 進行關鍵互動與響應式測試，搭配人工確認角色碰撞、視角與安全動線；不可只測 UI 上有無提示字樣。
6. 以未來可教學為目標，優先測試高風險場景：校門廣場錐鏈與受控入口、路口通行、公車車頭遮蔽、捷運車門關閉、車行中安全帶。

## 8. Codex 實作要求
建立 `src/safety/`：`rules.ts`、`evaluator.ts`、`feedback.ts`、`checkpoints.ts`，建立 `tests/safety/` 測試。所有場景事件統一呼叫安全評估器，禁止在個別關卡用硬編碼繞過安全守則。以資料驅動定義規則、錯誤回饋圖卡與多語系文案；遇到未核實事實不得假造。更新文件與驗收、執行 lint/typecheck/test/build、記錄實測結果。正式版不可在沒有安全驗收的情況下發布。
